# Measured batch evaluation

Run: 2026-11-13, 20 fixed scenarios, local deterministic model stub, no provider, no per-million prices configured. These numbers measure retrieval/prompt control flow against a fixed response fixture; they are not provider-model quality claims or priced cost estimates. Full per-scenario, per-call and token data are in `report.json`.

| Metric | v1 | v2 | Delta (v2 minus v1) | Better |
|---|---:|---:|---:|---|
| Groundedness | 0.7417 | 0.7542 | +0.0125 | v2 |
| Context relevance | 0.7300 | 0.5591 | -0.1709 | v1 |
| Faithfulness | 0.7917 | 0.8167 | +0.0250 | v2 |
| Hallucination rate | 0.6583 | 0.5167 | -0.1416 | v2 |

v2 deliberately instructs the research agent to search linked conditions, exceptions and facilities before deciding. Its context relevance falls because v2 retrieves more passages, including passages that do not overlap each scenario's required fact terms. On section 4.1, v1 routes to `request_further_evidence` (incorrect); v2 routes to `decline` (expected compensation outcome) and retains exact citations for 3.3.2 and 3.8.1. The response remains provisional and requires human review; it does not authorize or issue payment. Overall expected-route accuracy is 0.35 for v1 and 0.40 for v2.

Cost per 100 runs is $0.000000 for both variants because this fixture has no-priced usage and injected rates were zero. Under equal input pricing, the largest aggregate token driver is `research_tool_selection` (99,297 prompt tokens across the 40 variant runs, 110 calls); monetary step cost is zero for every step here. Inject actual provider prices and rerun for a priced cost comparison.

Metric definitions and formulas are in `README.md` in this directory. The machine-readable report is `report.json`; it was generated by `python -m eval.evaluate --mode llm --before v1 --after v2` against the local stub.
